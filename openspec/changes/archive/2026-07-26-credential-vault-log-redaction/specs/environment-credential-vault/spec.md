## MODIFIED Requirements

### Requirement: Wizard credentials use OS-backed encryption
Credential material captured or generated by the wizard, including SSH key passphrases and daemon session tokens, SHALL be encrypted through Electron `safeStorage` in the main process before persistence and SHALL never be stored in plaintext. Credential reference identifiers (store keys, UUIDs) SHALL NOT appear in log output at any log level. The `CredentialTamperedError` class is exempt — it propagates the reference programmatically in memory only.

#### Scenario: SSH key passphrase is supplied
- **WHEN** the user completes SSH setup with a key passphrase
- **THEN** the main process stores only an OS-encrypted credential payload outside the environment config

#### Scenario: Pairing returns a session token
- **WHEN** daemon pairing succeeds during the wizard
- **THEN** the main process stores the access token as an OS-encrypted credential payload

#### Scenario: OS encryption is unavailable
- **WHEN** the wizard needs to persist credential material and `safeStorage` is unavailable
- **THEN** setup fails without storing the credential in plaintext

#### Scenario: Credential integrity check fails
- **WHEN** the credential vault detects a tampered credential during retrieval
- **THEN** the error log SHALL NOT contain the credential reference UUID

#### Scenario: Credential migration to include HMAC
- **WHEN** a legacy credential entry without an HMAC is read for the first time
- **THEN** the info log SHALL NOT contain the credential reference UUID

#### Scenario: Orphan credential pruning
- **WHEN** the vault prunes orphaned credential entries
- **THEN** the warning log SHALL contain only the count of pruned entries, not the reference UUIDs
